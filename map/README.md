# map/ (차선 그래프 맵, 차량·관제 공유 단일 소스)

| 파일 | 지위 |
|---|---|
| `main_track_map.yaml` | 🔴 **맵 데이터의 유일한 정본.** 차량(rc_car)과 관제 서버가 이 파일 하나를 읽음<br>- **사본 금지**: 서버와 차량이 다른 맵을 보면 좌표 보정 무효 |
| `places.yaml` | 🔴 **시연 장소 6곳의 정본.** 관제 서버가 사전 저장해 `command.loc` 으로 송신하는 좌표 |
| `main_track_map_overlay.png` | 검수용. 그래프를 시연지도 위에 겹쳐 그린 그림 (하늘색=inner 서킷 / 자홍=outer 서킷 / 주황=직진, 파랑=좌회전, 빨강=우회전 커넥터) |
| `places_overlay.png` | 검수용. `places.yaml` 을 지도 위에 그린 그림. `rc_car/tools/build_places_overlay.py` 로 생성 |
| `segmentation_label_example.png` | 참고용. 세그 모델 학습 라벨 예시 1장 (횡단보도·정지선·화살표·점선·블록 경계 폴리곤). 모델·데이터셋은 저장소 미포함 |

## 이 파일의 지위

- 단일 소스가 보장하는 것은 좌표값의 정확성이 아니라 차량·관제 데이터의 동일성
  - 값이 틀려도 같은 파일이면 시스템은 일관되고, 실측 후 1회 갱신으로 양쪽 동시 수정
  - 각자 맵을 만들면 실측으로도 못 고치는 상호 불일치 발생. 사본 금지의 사유
- **좌표값은 잠정**: 시연지도 PNG 픽셀 판독값 (±2cm 추정)
  - 실제 기준은 GPS 서버 Initialize(기준 마커 0\~3을 노란선 꼭짓점에 배치)가 만드는 좌표계
  - 실지도와의 어긋남은 생성기 재보정 대신 차량 pose 수신부의 아핀 변환으로 흡수 (아래 "실측과의 정합")
- **구조는 실측과 무관**: 차선 연결·방향·회전 규칙의 근거는 노면 도색
  - 정차 금지 조각 판정(길이 0.22m < 차량 전장 0.28m)도 ±2cm 보정으로는 불변

## 수정 방법

YAML 수기 수정 금지. `rc_car/tools/build_demo_map.py`(생성기)를 고쳐 재생성

```
cd rc_car
python tools/build_demo_map.py            # YAML 재생성 (기하 검증 내장)
python tools/build_demo_map.py --overlay  # + 검수 오버레이 (PIL 필요)
python -m pytest tests/unit/test_lane_map.py   # 제약 전체 재검증
```

- 차선·커넥터 접점(접선 트림)이 서로 물려 있어 수작업 시 연속성 파손
- 좌표 근거(픽셀 판독 값)는 생성기 머리주석에 기재

## 스키마 (명세서 §11.2 기반)

- `lanes.*`: 일반 차선 중심선. `successors` 는 커넥터 id 목록 (차선 → 커넥터 → 차선 이분 그래프)
- `connectors.*`: 교차로 통과 경로. `maneuver: straight|left|right` (직진 16 · 좌 24 · 우 24 = 64개)
  - 2차로 도로로의 회전은 진입 차선별 2개 등록: 가까운 차선(기본) + 먼 차선(`*_far`)
- `blocks.*`: 녹색 승객 호출 영역 + curb 별 인접 정차 차선
- `stop_line_zones.*`: 정지선 예상 위치 (노면 도색 픽셀 판독 실측치)
- 확장(§11.2에 없음): `lanes.*.circuit`(링 계열 참고 라벨), `connectors.*.radius_m`

## 두 순환계와 회전 진입 차선 선택 (관제 서버 필독)

노면 화살표 규칙(안쪽 차로 직진+좌회전 / 바깥 직진+우회전)만으로는 시연 지도가 상호 도달 불가능한 두 순환계(inner / outer)로 완전 분리. 이를 잇는 다리가 회전 진입 차선 선택(`*_far` 커넥터 16개)

- 2차로 도로 회전 시 가까운 차선(기본) 외에 먼 차선 진입도 허용
- 그 결과 전체 32차선 강연결

초기(2026-07-28)에는 점선 구간의 대각 차선 변경(lane_change) 커넥터 8개도 등록했으나, 2026-08-04 실차에서 짧은 이음매 안 대각 기동이 물리적으로 무리(목표 5cm 초과, 인도 침범)로 확인되어 폐지

- 차선 a/b 조각 8쌍 병합, 40 → 32차선
- 현재 맵의 `vehicle_rules.lane_change_enabled: false` 가 그 흔적

관제 서버 규칙:

1. 좌표 보정(RoadSnapper)은 `destination_allowed: true` 차선으로 스냅 (교차로 사이 0.2m 스텁은 false. 서킷 구분은 제약 아님)
2. 시연 시작 위치는 임의 차선 가능
3. 참고: 승객 블록 curb 인접 차선은 전부 `circuit: inner`

⚠️ `*_far` 커넥터 16개 삭제 시 맵이 다시 두 순환계로 분리. 로더가 전 차선 쌍 도달성 검증으로 로드를 거부하고, `rc_car/tests/unit/test_lane_map.py` 가 이 구조를 테스트로 고정

## 시연 장소 표 `places.yaml` (관제 서버 필독)

시연 노선은 우리집과 목적지 5곳. 관제 서버가 이 6개 좌표를 사전 저장해 두고 `command.loc` 으로 송신

각 장소는 `call_point`(승객이 서는 블록 위 지점)와 `stop_point`(차량이 실제로 서는 차선 위 지점) 한 쌍. 서버 송신값은 `stop_point` (protocol_2 §9: 차량이 받는 loc 은 도로 위로 보정 완료된 좌표)

```
                정차점               차선              진행 방향
  우리집    (0.39, 2.25)  left_inner_nb_n    ↑ (90°)
  보건소    (3.70, 1.88)  mid_wb1_e          ← (180°)
  경로당    (1.20, 1.12)  mid_eb2_w          → (0°)
  시장     (3.70, 1.12)  mid_eb2_e          → (0°)
  면사무소   (1.20, 0.39)  bot_inner_wb_w     ← (180°)
  은행     (3.70, 0.39)  bot_inner_wb_e     ← (180°)
```

- 우리집은 2026-08-09 에 3번 차선(`top_inner_eb_w`)에서 20번 차선 중앙으로 이동. 착지 실패가 잦던 `20->3` 우회전을 노선에서 제외하려는 목적
- 보건소·경로당·시장은 2026-08-04 차선 병합으로 이음매 정차가 허용되면서 블록 중앙 최적 좌표로 원복

### 🔴 정차점 배치 규칙 (차선 조각 끝 회피)

> **정차점은 차선 조각 끝에서 `arrival_radius_m`(0.40) + 여유(`end_margin_m` 0.05) 이상 이격**

차선은 이음매(connector)를 사이에 두고 조각으로 분할. 정차점이 조각 끝에 놓이면 도착 반경 안에서 조금만 지나쳐 서도 이음매 위 위치가 되고, 도착 판정 §19-2 가 목표 **차선** 매칭을 요구하므로 게이트 미개방 · `complete` 미송신. 후진이 없어 자력 이탈도 불가한 교착 상태 (2026-07-29 초안 좌표에서 재현 확인, 1cm 지나침에도 도착 판정 실패)

교착 자체는 이후 도착 게이트 보완(이음매 위에서 진입·진출 차선을 함께 인정하는 `LaneMap.arrival_lane_candidates`, 2026-07-30)으로 이중 방어되지만 배치 규칙은 유지

반경 0.40 기준의 알려진 예외 2건은 `places.yaml` 주석과 회귀 방지 테스트(`test_arbitrary_destination`)에 근거와 함께 명시

- 우리집 20번 차선은 길이 0.21m 라 제약 미충족이나, 반경이 인접 이음매를 전부 덮어 무해 (8/10 주행 3회 실증)
- 일부 차선 끝 2cm 밴드의 원단 스윕 9좌표

조각 **시작** 쪽은 안전 (직전 이음매의 진출 차선 = 목표 차선이라 게이트 개방). `rc_car/tests/unit/test_places.py` 가 이 규칙을 강제

### 수정 방법

`places.yaml` 수정 후 검증·그림 재생성을 함께 실행

```
cd rc_car
python -m pytest tests/unit/test_places.py    # 안전 규칙·경로 존재 검증
python tools/build_places_overlay.py          # 그림 재생성 (PIL 필요)
```

`call_point` 는 실측 대상(ArUco 마커 + `probe_gps.py`), `stop_point` 는 그로부터 계산하는 값. 실측으로 `call_point` 변경 시 `stop_point` 도 인접 차선에 재투영해 위 규칙 충족 필요

## 실측과의 정합 (프로젝트 종료 시점 기준)

- 좌표는 지도 이미지 픽셀 판독값 (±2cm 추정). 실주행에서 확인된 서버 좌표계와의 어긋남(축척 x 3.0% / y 4.7% 부족)은 맵 재생성 대신 차량 pose 수신부의 아핀 변환으로 흡수
  - `rc_car/config/network.yaml` 의 `frame_transform`, 잔차 약 3.5cm
  - 맵 소비자(관제·정차점) 전체 무수정 유지
- 커넥터 반경대로의 원호 추종은 실차에서 폐기. 회전은 실측 반경 기반 고정 조향(`rc_car/config/turn_table.yaml`)으로 대체
  - 커넥터 기하는 경로 위상과 회전 지시에만 사용 (`lane_route` 가 원호를 버리고 Turn 으로 변환)
